## Что изменено в сайте

Два файла, по одному вставленному блоку, ничего не удалено:

```
 fmarsm.github.io-main/contacts-eng.html | 17 +++++++++++++++++
 fmarsm.github.io-main/contacts.html     | 17 +++++++++++++++++
 2 files changed, 34 insertions(+)
```

Вставлен `<script>` сразу после блока с `handleChange()`:

```js
const dateIn = document.querySelector('input[name="Date1"]');
const dateOut = document.querySelector('input[name="Date2"]');

function checkDates() {
  dateOut.min = dateIn.value;
  if (dateIn.value && dateOut.value && dateOut.value < dateIn.value) {
    dateOut.setCustomValidity('Дата отъезда не может быть раньше даты заезда');
  } else {
    dateOut.setCustomValidity('');
  }
}

dateIn.addEventListener('input', checkDates);
dateOut.addEventListener('input', checkDates);
checkDates();
```

На `contacts-eng.html` — то же самое с текстом
`Departure date cannot be earlier than the arrival date`.

### Почему так, а не иначе

- **`setCustomValidity`, а не проверка внутри обработчика `submit`.** Тест-план (TC-11)
  ждёт, что «поле даты отъезда помечено как некорректное с понятным пояснением», и сайт
  уже опирается на штатную HTML5-валидацию — TC-10 это подтверждает. Самописное сообщение
  в `#success` было бы чужой для страницы механикой и не помечало бы само поле.
- **`min` в дополнение к сообщению** — чтобы календарь браузера сразу гасил недопустимые
  дни, а не только ругался после ввода.
- **Обе языковые версии.** Баг задокументирован для `contacts.html`, но `contacts-eng.html`
  содержит идентичную разметку и тот же дефект — это находка B-3 из
  [independent-audit.md](independent-audit.md). Фикс только русской страницы оставил бы
  тот же баг на зеркале.

### Что сознательно НЕ входит в фикс

- **Прошлые даты по-прежнему принимаются.** В «Фактическом результате» бага 5 эта фраза есть,
  но в «Ожидаемом результате» её нет. Запрещать ли бронь задним числом — продуктовое решение
  (можно ли бронировать на сегодня, в каком часовом поясе), это выбор владельца сайта.
- **Равные даты (заезд = отъезд, бронь на 0 ночей) остаются валидными.** Баг сформулирован
  как «отъезд *раньше* заезда», и автотест `BUG-03` считает `d2 >= d1` допустимым. Сделать
  правило строже оракула проверки — значит поменять требование задним числом.

Оба пункта вынесены в «Открытые вопросы» ниже.
