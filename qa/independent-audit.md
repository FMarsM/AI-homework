# Независимый аудит QA-артефактов

Проверка папки `qa/` на соответствие [SPEC.md](../SPEC.md) и [AGENTS.md](../AGENTS.md).

- **Дата:** 2026-08-17
- **Кто проверял:** Claude Opus 5, чистая сессия — без истории обсуждения сессии 4
  (закрывает правило курса «Независимый взгляд», которое в `STATE.md` числится незакрытым)
- **Что проверялось:** `qa/test-plan.md`, `qa/bug-reports.md`, `qa/playwright/*.spec.js`,
  `qa/screenshots/`, плюс перекрёстные ссылки в `sessions/STATE.md` и `sessions/session-4.md`
- **Аудируемые файлы не изменялись.** Прогон автотестов сделан на копиях в отдельном
  каталоге, чтобы не затереть сохранённые скриншоты-доказательства (см. находку B-6).

## Метод

Аудит не полагается на утверждения отчёта. Каждый вывод проверялся заново:

1. Прогон `bugs.spec.js` и `evidence.spec.js` из изолированной копии
   (`node_modules` подключён junction'ом к существующей установке, скриншоты
   перенаправлены в свой каталог).
2. Сверка причин каждого бага с исходником сайта (`grep`/`sed` по HTML и CSS).
3. Независимая проверка ключевой гипотезы `SPEC.md` про обратные слэши: выборка
   всех ссылок на `assets` из 10 страниц, дедупликация, запрос каждого файла к серверу.
4. Просмотр скриншотов глазами — показывают ли они заявленный дефект.
5. Сверка перекрёстных ссылок между `qa/` и `sessions/`.

**Границы аудита.** Один браузер (Chromium 151 из Playwright), только локальный
`python -m http.server`; поведение на боевом GitHub Pages не проверялось. Форма
бронирования не отправлялась — лимит из `AGENTS.md` не расходовался.

## Находки

### A. Существенные — нарушают явные требования SPEC/AGENTS

#### A-1. Обязательного списка расхождений «отчитались готово / проверка опровергла» не существует

`SPEC.md` («Критерии приёмки») и `AGENTS.md` («Что проверить перед финальным ответом»)
требуют его отдельным пунктом. Фактически:

- в `sessions/session-4.md` такого раздела нет — ни в рабочей копии, ни в коммите `a7fdf5f`
  (проверено `git show HEAD:sessions/session-4.md`, заголовков всего 11, нужного среди них нет);
- `sessions/STATE.md:26-27` утверждает обратное: «`session-4.md` заполнен целиком,
  **включая таблицу расхождений** … (6 записей)»;
- `qa/bug-reports.md:346-348` отправляет читателя именно туда за разбором главной
  гипотезы `SPEC.md`: «Подробный разбор — в журнале сессии, раздел „Расхождения…"».

Три следствия сразу: невыполненный критерий приёмки, ложное утверждение в `STATE.md`
и битая ссылка в баг-репортах. Это ровно тот класс расхождения, который аудит и должен
ловить: отчёт о состоянии не совпадает с состоянием.

**Что сделать:** восстановить 6 записей (они были — раз в `STATE.md` названо их число)
либо честно записать, что материал утрачен, и исправить `STATE.md`.

#### A-2. Главная гипотеза SPEC закрыта утверждением без сохранённого доказательства

`SPEC.md` выносит обратные слэши в путях (`assets\img\...`) в «Открытые вопросы» и делает
проверку приоритетной. `qa/test-plan.md` (TC-02) обещает артефакт — «network/console-лог
по каждой странице». **Такого файла в `qa/` нет.** В `bug-reports.md` остались только числа
без источника: «все 152 локальных ресурса на 10 страницах отдаются со статусом 200».

Вывод при этом **верен** — я перепроверил независимо:

```
всего ссылок на assets в разметке: 132
уникальных:                        53
не-200:                            0
```

Причина, которой в отчёте нет: браузер по спецификации WHATWG URL нормализует `\` в `/`
для http(s), поэтому запрос уходит как `assets/css/style.css` и на GitHub Pages тоже.
Косвенное подтверждение из самого прогона: `evidence.spec.js:64` сверяет вычисленный
цвет `rgb(214,123,123)` со значением из `style.css` — тест зелёный, значит CSS
по «сломанному» пути загрузился. Сервер отдаёт 301 только на явно закодированный
`%5C` — то есть на путь, который браузер никогда не отправит.

Итог: правильный вывод, нулевая проверяемость. Число 152 воспроизвести из артефактов
невозможно (в разметке 53 уникальных файла + подгружаемые из CSS + CDN).

#### A-3. Реестра результатов проверок не существует

`qa/test-plan.md`, «Критерии завершения прогона», первый пункт: «Все 12 проверок
выполнены, **результат каждой зафиксирован (pass / fail)**». Такой таблицы нет ни в одном
файле. Итоги TC-02 и TC-04 растворены в прозаическом списке «Что проверялось и оказалось
исправным», по остальным приходится восстанавливать связь через имена автотестов.

Заодно: чек-боксы в `test-plan.md:181-186` и в `SPEC.md:131-144` так и остались пустыми
`[ ]` — ни один критерий формально не отмечен как закрытый.

### B. Средние — снижают ценность и трассируемость находок

#### B-1. Три несогласованные нумерации багов

`AGENTS.md`, формат баг-репорта, п.1: «ID бага — порядковый номер, **сквозной по всему
проекту**». Фактически:

| ID в отчёте | Автотест | Файл-скриншот |
|---|---|---|
| Баг 2 (500 → «Спасибо») | `BUG-01` | `bug-01-http-500-shows-success.png` |
| Баг 3 (сетевой сбой) | `BUG-08` | `bug-08-network-fail-silent.png` |
| Баг 4 (количество гостей) | `BUG-02` | `bug-02-guests-accepts-letters.png` |
| Баг 7 (логотип ENG) | `BUG-04` | `bug-04-eng-logo-href.png` |

Файл `bug-01-*.png` — доказательство к багу **№2**, `bug-08-*.png` — к багу **№3**.
Постороннему человеку (а баг-репорт пишется именно для него) трассировка сломана:
имя файла указывает на чужой ID. Сводная таблица в начале отчёта это чинит лишь отчасти.

#### B-2. Два скриншота-«подтверждения» не показывают дефект

- `bug-05-footer-dead-link.png` — открыт верх `chaika1.html`. **Футера с дефектной
  ссылкой в кадре нет вообще**: `bugs.spec.js:100` снимает кадр до клика и без скролла
  к футеру.
- `bug-04-eng-logo-href.png` — снят до клика (`bugs.spec.js:88`), показывает обычную
  английскую главную. Дефект (переход на русскую версию) в кадр не попадает по построению.

Формально п.8 формата закрыт фрагментом разметки и красным выводом теста, так что
баг-репорт остаётся завершённым. Но файл, названный «Подтверждением», ничего не
подтверждает — а именно на него смотрят первым.

Для контраста, эти два сделаны правильно и дефект видно: `bug-01-http-500-shows-success.png`
(зелёное «Спасибо…» под кнопкой при ответе 500) и `bug-06-menu-stuck-after-resize.png`
(на 375 px одновременно гамбургер и раскрытый список).

**Причина в коде, а не в удаче:** `screenshot()` вызывается до действия, которое
вскрывает дефект. Лечится переносом вызова после `click()` и `scrollIntoViewIfNeeded()`
для футера.

#### B-3. Формные баги задокументированы вдвое уже, чем существуют

Баги 2, 3, 4, 5 описаны только для `contacts.html`. Проверил английскую страницу —
дефекты там те же, файл идентичен по этим местам:

```
contacts-eng.html:88   function handleChange(input)          → тот же зажим границ
contacts-eng.html:67   <input type="date" name="Date1" …>    → без min
contacts-eng.html:69   <input type="date" name="Date2" …>    → без min
contacts-eng.html:100  .then(response => { … })              → без проверки response.ok
```

`SPEC.md` («Допущения») прямо считает `-eng.html` зеркальной версией той же
функциональности — значит область дефекта надо было указать. В «Предусловиях» стоит
только русская страница, в «Фактическом результате» область не расширена.

Показательно, что в багах 7 и 8 область расписана точно и по страницам («на всех пяти
англоязычных… сделана правильно») — то есть автор умеет это делать, просто для формы
не сделал.

#### B-4. Баг 1 (Blocker) стоит на границе периметра, и неоднозначность не вынесена человеку

`SPEC.md`, «Чего точно не делаем»: не проверяем содержимое сторонних сервисов —
«доходит ли сообщение до WhatsApp/Telegram». «Доходит ли заявка в Google-таблицу» —
тот же класс вопроса. Сам баг-репорт в блоке «Граница достоверности» признаёт, что
отличить отозванный деплой от настройки доступа или ограничения Google из этого
окружения нельзя.

По `AGENTS.md` («Когда агент обязан остановиться и спросить») это должно было попасть
в список неоднозначностей и уйти вопросом владельцу, а не быть закрыто степенью
Blocker и внесено в сводку. Blocker — самая тяжёлая оценка в отчёте, и она поставлена
факту, причина которого не установлена и который, возможно, вне периметра.

Важно: баги 2 и 3 (реакция интерфейса на ошибку и на сетевой сбой) от этого не зависят
и остаются полностью валидными — они воспроизводятся на подменённом ответе.

## Что подтвердилось при перепроверке

Раздел не для красоты: аудит должен отделять реальные находки от переписанных утверждений.

**Автотесты воспроизводятся один в один.** Изолированный прогон копий:

```
bugs.spec.js      → 8 failed  (BUG-01 … BUG-08)
evidence.spec.js  → 13 passed (20.0s)
```

Тексты падений совпадают с фрагментами, процитированными в `bug-reports.md`, вплоть
до значений (`slide1: 1` вместо `2`, `computed: "block"` вместо `"none"`,
`visibleToUser: ""`). Цитаты в отчёте не приукрашены.

**Причины багов совпадают с исходником.** Проверено построчно:

| Баг | Заявленная причина | Проверка |
|---|---|---|
| 2, 3 | `.then(response => …)` без `response.ok`, `.catch` только в консоль | `contacts.html:99-108` — подтверждено |
| 4 | `type="text"` + сравнение строки с числом | `contacts.html:71`, `88-91` — подтверждено |
| 5 | у `Date1`/`Date2` нет `min` и взаимной проверки | `contacts.html:67-69` — подтверждено |
| 6 | ветка `clientWidth > 1280` внутри `click`, слушателя `resize` нет | `index.html:43-53` — подтверждено |
| 7 | `<h1><a href="index.html">` на `index-eng.html` | подтверждено; на 4 других ENG-страницах ссылка верная |
| 8 | `href="#"` в футере | подтверждено ровно на `chaika1/2/3.html` и `contacts.html`; заявленная область точна |
| 9 | селекторы `nth-child(16)` при 3 слайдах | `style.css:451-452`, всего 8 вхождений `nth-child(16)`, слайдов на главной 3 |

**Наблюдения Н-1…Н-4 точны.** `<html lang="en">` — на всех 10 страницах;
картинок 122, атрибут `alt` — ни у одной; `id="text"` — у 7 элементов формы;
`action="POST"` вместо `method` — на месте.

**Правила проекта соблюдены:**

- сайт не тронут — `git status` чист по всему `fmarsm.github.io-main/`;
- лимит отправок формы соблюдён: 1 из 10, с меткой в ФИО, причём `real-submit.spec.js:15`
  закрыт переменной `QA_REAL_SUBMIT` — обычный `npx playwright test` его не выстрелит.
  Аккуратное решение;
- структура `qa/` и имена файлов соответствуют «Соглашениям проекта», язык документов — русский;
- все 9 баг-репортов содержат все 8 обязательных пунктов формата;
- скриншоты есть на всех четырёх ширинах (index и contacts × 375/768/1024/1440).

**Разбор гипотезы про обратные слэши сделан правильно** и, что важнее, отрицательный
результат не спрятан — в отчёте есть отдельный раздел «Что проверялось и оказалось
исправным». Претензия только к отсутствию доказательства (A-2), не к выводу.
