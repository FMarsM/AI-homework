## Среда прогона

| Параметр | Значение |
|---|---|
| Объект | `fmarsm.github.io-main/`, 10 HTML-страниц, без сборки и бэкенда |
| Хостинг для прогона | `python -m http.server 8080 --directory fmarsm.github.io-main` → `http://localhost:8080` |
| Python | 3.13.2 |
| Браузер | встроенный Browser MCP-инструмент агента (Chromium-движок) |
| ОС | Windows 10 Pro 10.0.19045 |
| Ширины | 375 / 768 / 1024 / 1440 px |
| Автотест | Node.js v24.19.0 + `@playwright/test` (ставится в `qa/playwright/`) |

**Важно про среду:** ключевой подозреваемый дефект (обратные слэши в путях) по природе
зависит от файловой системы. Локальный прогон на Windows — не то же самое, что
GitHub Pages на Linux. Поэтому по этому пункту фиксируется отдельно: что видно
локально и что из этого следует для боевого хостинга.

## Проверки

★ — негативная или граничная проверка. Их 7 из 12, требование «не меньше трети» выполнено.

### TC-01 — Смоук главной страницы на четырёх ширинах

- **Предусловия:** сервер поднят, открыт `http://localhost:8080/index.html`, кэш чистый.
- **Шаги:** для каждой ширины 375 / 768 / 1024 / 1440 px открыть главную, снять скриншот.
- **Ожидаемо:** страница рендерится, видны логотип, переключатель языка, меню
  (на 1440 — горизонтальное, на ≤1280 — кнопка-гамбургер), слайдер, текстовый блок,
  карта, футер. Вёрстка не разъезжается, горизонтальной прокрутки нет.
- **Артефакт:** `qa/screenshots/viewport-{375,768,1024,1440}-index.png`.

### TC-02 — Загрузка статических ресурсов на всех 10 страницах ★

- **Предусловия:** сервер поднят, открыта консоль и network-лог, ширина 1440.
- **Шаги:** последовательно открыть все 10 страниц (`index`, `chaika1`, `chaika2`,
  `chaika3`, `contacts` — RU и ENG); на каждой собрать список запросов со статусом
  ≥ 400 и ошибок в консоли; отдельно проверить, применился ли `style.css`
  (сравнить вычисленный стиль с ожидаемым из файла).
- **Ожидаемо:** ни одного 404, CSS применён, шрифты и изображения загружены.
- **Основание приоритета:** `SPEC.md` — пути в разметке записаны через обратный
  слэш (`assets\css\style.css`, `assets\img\...`), что не является корректным URL.
- **Артефакт:** network/console-лог по каждой странице.

### TC-03 — Меню на 1440 px: адреса и подсветка активного пункта

- **Предусловия:** ширина 1440, открыта `index.html`.
- **Шаги:** пройти по всем 5 пунктам меню; на каждой странице проверить, какой
  пункт помечен `li.selected` и как он выглядит.
- **Ожидаемо:** каждый пункт ведёт на свою страницу (HTTP 200), активный пункт
  соответствует текущей странице и визуально отличается.

### TC-04 — Целостность ссылок логотипа и футера на всех 10 страницах ★

- **Предусловия:** ширина 1440.
- **Шаги:** на каждой из 10 страниц собрать `href` логотипа и всех ссылок футера;
  проверить каждый внутренний адрес запросом (ожидается 200); отдельно отметить
  пустые ссылки (`href="#"`) и ссылки, уводящие в другую языковую версию.
- **Ожидаемо:** внутренние ссылки существуют и ведут в ту же языковую версию;
  ссылка «Контакты» в футере открывает `contacts.html` (соответственно
  `contacts-eng.html`), а не остаётся заглушкой.

### TC-05 — Переключатель языка туда-обратно с внутренней страницы

- **Предусловия:** ширина 1440, открыта `chaika2.html`.
- **Шаги:** нажать флаг ENG → проверить URL и язык контента; нажать флаг RUS →
  проверить URL; повторить на `contacts.html` и `chaika3.html`.
- **Ожидаемо:** остаёшься в том же разделе (`chaika2.html` ↔ `chaika2-eng.html`),
  сброса на главную нет.

### TC-06 — Прямой заход на внутреннюю страницу минуя главную ★

- **Предусловия:** новая вкладка без истории, ширина 1440.
- **Шаги:** открыть напрямую `http://localhost:8080/chaika2.html`; проверить меню,
  переключатель языка, логотип, футер; переключить язык и вернуться назад кнопкой браузера.
- **Ожидаемо:** всё работает без наличия главной страницы в истории; кнопка «Назад»
  возвращает на `chaika2.html`.

### TC-07 — Мобильное меню на 375 px: открыть / закрыть кликом мимо / открыть повторно

- **Предусловия:** ширина 375, открыта `index.html`.
- **Шаги:** нажать кнопку `#navigation` → меню раскрылось; кликнуть мимо меню →
  закрылось; нажать `#navigation` снова → раскрылось; выбрать пункт меню → переход.
- **Ожидаемо:** каждый шаг даёт описанный эффект, меню не залипает.
- **Артефакт:** `qa/screenshots/viewport-375-menu-open.png`.

### TC-08 — Состояние меню при изменении ширины 1440 ↔ 375 ★

- **Предусловия:** открыта `index.html`.
- **Шаги:** (а) на 1440 кликнуть по пустому месту страницы, затем сузить окно до
  375 — посмотреть на меню; (б) на 375 открыть гамбургер-меню, затем расширить
  окно до 1440 — посмотреть на меню.
- **Ожидаемо:** после изменения ширины меню соответствует новой ширине —
  на 375 свёрнуто под кнопку, на 1440 горизонтальное; ручного клика для
  «починки» не требуется.
- **Основание:** в скрипте страницы ветка `clientWidth > 1280` выполняется только
  внутри обработчика `click`; слушателя `resize` нет — сценарий 5 из `SPEC.md`.
- **Артефакт:** скриншоты до и после ресайза.

### TC-09 — Слайдер главной: точки, стрелки, последний слайд и обратно ★

- **Предусловия:** ширина 1440, открыта `index.html`, слайдер в первом состоянии.
- **Шаги:** переключиться точками 1 → 2 → 3; вернуться точками 3 → 1;
  проделать то же стрелками «вперёд»/«назад»; на последнем (3-м) слайде проверить
  наличие стрелки «вперёд», на первом — стрелки «назад».
- **Ожидаемо:** доступны оба направления на всех слайдах, с последнего слайда
  можно двинуться дальше (или вернуться к первому), карточка подписана правильным
  названием коттеджа.

### TC-10 — Отправка формы с пустыми обязательными полями ★

- **Предусловия:** ширина 1440, открыта `contacts.html`, форма пуста.
- **Шаги:** нажать «Отправить», не заполнив ничего; затем заполнить только ФИО и
  снова нажать «Отправить»; следить за network-логом.
- **Ожидаемо:** форма не отправляется, браузер показывает стандартную
  HTML5-валидацию на первом незаполненном обязательном поле, POST-запрос на
  Google Apps Script **не уходит**, сообщение об успехе не появляется.

### TC-11 — Валидация «Количество заселяющихся» и дат заезда/отъезда ★

- **Предусловия:** ширина 1440, открыта `contacts.html`.
- **Шаги:** в поле «Количество заселяющихся» по очереди ввести `-5`, `0`, `31`,
  `abc`, `2.5`, каждый раз уводя фокус (чтобы сработал `onchange`), и фиксировать
  итоговое значение поля; затем выставить дату заезда `2026-09-10`, дату отъезда
  `2026-09-01` и попытаться отправить.
- **Ожидаемо:** нечисловое значение и дробное число не принимаются либо явно
  отклоняются; `0` не проходит как валидное количество гостей; дата отъезда раньше
  даты заезда отклоняется с понятным сообщением.
- **Основание:** `handleChange()` в `contacts.html` сравнивает строку с числом и
  только зажимает диапазон, поле объявлено как `type="text"`; у полей даты нет
  ни `min`, ни взаимной проверки — сценарий 9 из `SPEC.md`.

### TC-12 — Реакция формы на ошибку сервера ★

- **Предусловия:** открыта `contacts.html`, все поля заполнены валидно, ФИО
  промаркировано как тестовое.
- **Шаги:** подменить ответ Google Apps Script на HTTP 500 (перехват запроса в
  Playwright, боевой эндпоинт при этом не вызывается) и отправить форму; отдельно
  повторить с оборванным соединением (`route.abort()`).
- **Ожидаемо:** пользователь видит сообщение об ошибке и понимает, что заявка не
  принята; текста «Спасибо, ваша заявка зарегистрирована!» при неуспешном ответе быть не должно.
- **Основание:** обработчик `.then(response => ...)` в `contacts.html` не смотрит
  на `response.ok`, а `.catch` пишет только в консоль.
