# BUG-01. Форма заявки принимает дату отъезда раньше даты заезда

| Поле | Значение |
|---|---|
| **ID** | BUG-01 |
| **Компонент** | Страница контактов → форма «Оставьте свои данные и мы вам перезвоним!» |
| **Приоритет** | High |
| **Серьёзность** | Critical |
| **Тип** | Функциональный дефект (валидация) |
| **Окружение** | Windows 10 Pro 22H2, Chromium, viewport 1280×720, `http://127.0.0.1:8777/contacts.html` |
| **Найдено** | 17.08.2026 |
| **Связанный тест-кейс** | TC-08 |
| **Автотест** | `autotests/test_booking_dates.py` |

## Описание

Форма бронирования не проверяет взаимосвязь полей «Дата заезда» и «Дата отъезда».
Заявку можно отправить с датой отъезда раньше даты заезда, то есть с отрицательным
сроком проживания. Ошибочная заявка уходит в Google-таблицу менеджера и требует
ручного разбора; при подсчёте стоимости по количеству ночей такая запись
даст бессмысленный или отрицательный результат.

Дополнительно поля не ограничены снизу текущей датой — принимается бронь на 01.01.2000.

## Шаги воспроизведения

1. Открыть `contacts.html` (RU) или `contacts-eng.html` (EN).
2. В поле «ФИО» ввести `Иванов Иван`.
3. В поле «Номер телефона» ввести `+79000000000`.
4. В поле «Дата заезда» указать **10.09.2026**.
5. В поле «Дата отъезда» указать **01.09.2026**.
6. В поле «Количество заселяющихся» ввести `4`.
7. Нажать кнопку «Отправить».

## Фактический результат

Форма считается валидной и отправляется. Браузер не показывает ошибку,
появляется сообщение «Спасибо, ваша заявка зарегистрирована!».

Проверка в консоли на шаге 7:

```js
document.forms['submit-to-google-sheet'].checkValidity()  // → true
// Date1 = "2026-09-10", Date2 = "2026-09-01"
```

Тот же результат для даты заезда в прошлом:

```js
document.forms['submit-to-google-sheet'].Date1.checkValidity()  // → true при value = "2000-01-01"
```

## Ожидаемый результат

Отправка блокируется, рядом с полем «Дата отъезда» показано понятное сообщение,
например «Дата отъезда должна быть позже даты заезда». Даты в прошлом не принимаются.

## Причина (анализ кода)

`contacts.html:67-69` — оба поля объявлены без ограничений и без кросс-валидации:

```html
<input type="date" id="text" name="Date1" required autocomplete="off">
<input type="date" id="text" name="Date2" required autocomplete="off">
```

Ни `min`, ни обработчика сравнения дат в скриптах страницы нет —
единственная JS-валидация в файле (`handleChange`) относится к количеству гостей.

## Предлагаемое исправление

1. Задать `min` для даты заезда равным сегодняшней дате при загрузке страницы.
2. По `change` на «Дате заезда» проставлять `Date2.min = Date1.value` (либо следующий день).
3. Продублировать проверку в обработчике `submit` через `setCustomValidity()` —
   чтобы форма не уходила даже при обходе атрибутов.
4. Аналогично поправить `contacts-eng.html` (дефект воспроизводится и там).

## Воспроизводимость

100 % (5 из 5 попыток), RU и EN версии страницы.
