# BUG-03. Поле «Количество заселяющихся» принимает буквы и молча подменяет введённое число

| Поле | Значение |
|---|---|
| **ID** | BUG-03 |
| **Компонент** | Страница контактов → форма заявки, поле «Количество заселяющихся» |
| **Приоритет** | High |
| **Серьёзность** | Major |
| **Тип** | Функциональный дефект (валидация) + UX |
| **Окружение** | Windows 10 Pro 22H2, Chromium, viewport 1280×720, `http://127.0.0.1:8777/contacts.html` |
| **Найдено** | 17.08.2026 |
| **Связанный тест-кейс** | TC-09 |

## Описание

Поле объявлено как `type="text"` вместо `type="number"`, поэтому браузерная валидация
не отсекает нечисловой ввод. Единственная защита — JS-функция `handleChange`, которая
срабатывает только по событию `change` и сравнивает **строку** с числом.

Из этого следуют три проблемы:

1. **Буквы и спецсимволы проходят валидацию.** Значение `abc!!` остаётся в поле,
   форма отправляется — менеджер получает заявку без количества гостей.
2. **Ввод `-5` превращается в `0`.** Заявка на ноль гостей считается корректной.
3. **Ввод `999` молча превращается в `30`** — пользователь не уведомлён о том,
   что его значение изменено, и может не заметить подмену перед отправкой.

## Шаги воспроизведения

1. Открыть `contacts.html`.
2. Заполнить ФИО, телефон и обе даты валидными значениями.
3. В поле «Количество заселяющихся» ввести `abc!!`, затем снять фокус (Tab).
4. Нажать «Отправить».
5. Повторить шаги 3–4 со значениями `-5` и `999`.

## Фактический результат

| Ввод | Значение поля после снятия фокуса | Форма валидна |
|---|---|---|
| `abc!!` | `abc!!` | `true` — отправляется |
| `-5` | `0` | `true` — отправляется |
| `999` | `30` (без уведомления) | `true` — отправляется |

Проверка в консоли:

```js
const f = document.forms['submit-to-google-sheet'];
f.Number_of_clients.value = 'abc!!';
f.Number_of_clients.dispatchEvent(new Event('change', {bubbles: true}));
f.Number_of_clients.value  // → "abc!!"
f.checkValidity()          // → true
```

## Ожидаемый результат

Поле принимает только целое число от 1 до 30. Нечисловой ввод, `0` и отрицательные
значения блокируют отправку с понятным сообщением. При превышении максимума пользователю
показывается ошибка, а не тихая подмена значения.

## Причина (анализ кода)

`contacts.html:71` — тип поля:

```html
<input type="text" id="text" name="Number_of_clients" required autocomplete="off" onchange="handleChange(this)">
```

`contacts.html:88-91` — обработчик, сравнивающий строку с числом
(`'abc!!' < 0` и `'abc!!' > 30` оба дают `false`, поэтому нечисловой ввод не трогается):

```js
function handleChange(input) {
  if (input.value < 0) input.value = 0;
  if (input.value > 30) input.value = 30;
}
```

## Предлагаемое исправление

1. Заменить на `<input type="number" name="Number_of_clients" min="1" max="30" step="1" required>` —
   браузер сам отсечёт буквы и выход за границы.
2. Убрать `handleChange` либо заменить тихую подмену на `setCustomValidity()`
   с текстом «Укажите количество гостей от 1 до 30».
3. Продублировать проверку на бэкенде (Google Apps Script), так как клиентскую
   валидацию можно обойти.
4. Аналогично поправить `contacts-eng.html:71` — дефект воспроизводится и там.
