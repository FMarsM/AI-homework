# Тест-план — fmarsm.github.io-main (наивный прогон)

Короткий чек-лист для ручного прохода по сайту «Чайка» (10 HTML-страниц,
RU/ENG, без бэкенда, форма бронирования на Google Apps Script).
Сайт поднят локально: `python -m http.server 8080 --directory fmarsm.github.io-main`.

| № | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `index.html` | Страница, слайдер и меню отображаются без ошибок в консоли |
| 2 | Прямой заход на внутреннюю страницу (`chaika2.html`), минуя главную | Меню и переключатель языка работают корректно |
| 3 | Переключение языка (RU↔ENG) с внутренней страницы | Остаёмся на эквивалентном разделе (`chaikaN` ↔ `chaikaN-eng`), а не сбрасываемся на главную |
| 4 | Навигация по всем пунктам меню на 1440 px | Каждый пункт ведёт на свою страницу |
| 5 | Мобильное меню на 375 px: открыть кнопкой, закрыть кликом мимо | Меню открывается/закрывается корректно |
| 6 | Открыть мобильное меню и увеличить ширину окна до 1440 px без клика | Меню должно вернуться к десктопному виду (нет обработчика `resize` — потенциальный риск) |
| 7 | Форма бронирования: отправка с пустыми обязательными полями | Браузер блокирует отправку через HTML5-валидацию (`required`) |
| 8 | Поле «Количество заселяющихся»: отрицательное число, число > 30 | Значение обрезается до 0 / 30 (`handleChange`) |
| 9 | Поле «Количество заселяющихся»: нечисловой текст (`abc`) | **Баг** — значение не обрезается и не валидируется |
| 10 | Проверка `id` полей формы через DOM (`#text`) | Ожидается уникальный `id` на элемент — **баг**: 7 полей используют один и тот же `id="text"` |
| 11 | Загрузка статических ресурсов (картинки/шрифты/CSS) на всех 10 страницах | 200 OK на все `src`/`href`-ресурсы (пути в разметке через `\`, но браузеры нормализуют `\` в `/` для `http(s)`-схемы — не баг, проверено фетчем всех ресурсов на всех страницах) |
| 12 | Ссылка «Контакты» в футере на `contacts.html` | Должна вести на `contacts.html` (как на всех остальных страницах и на `contacts-eng.html`) — **баг**: ведёт на `#` |
| 13 | Обход всех ссылок меню/футера на каждой странице | Ни одна не ведёт на несуществующую страницу |

Пункты 3, 5, 6, 8, 9, 12 — негативные/граничные (не менее трети от 13).

## Что проверено вне таблицы

- Консоль браузера (`No console logs`) и network-лог на `index.html`,
  `contacts.html` — ошибок не найдено.
- Автоматизированная сверка всех `src="..."`/`href="..."` (кроме `.html` и
  внешних) на всех 10 страницах через `fetch()` в браузере — 0 не-200 ответов.

## Ограничения этого прогона

- Скриншот-инструмент браузерного MCP в этой сессии не смог сделать снимок
  экрана (`the Browser pane is not displayed, so the page is not compositing
  frames`) — как подтверждение багов использованы DOM/consol-логи (вывод
  `read_page`, `javascript_tool`, `network_requests`), а не картинки.
- Это «наивный» прогон по короткому промпту, без полного набора негативных
  сценариев из `SPEC.md` (клавиатурная навигация, слайдер по точкам,
  реальная отправка формы) — сокращённый набор, ориентир ~10–15 проверок.
